How Claude Code tokens work

Every time you send a message, Claude re-reads your entire conversation from the beginning, not just your latest message. That's why tokens add up fast.

A 3-message conversation
Message 1 You send "Help me fix this bug." Claude reads it fresh (input) and saves the conversation to cache (cache write). ~4K tokens
Message 2 You reply "Try the other file." Claude reuses message 1 from cache (cache read), processes only your new message fresh (input), then saves the updated conversation (cache write). ~8K tokens
Message 3 Claude reuses messages 1–2 from cache (cache read) and processes your new message fresh (input). Claude's reply is output. ~14K tokens
Without caching, every message would be processed at full price.
Input: your message and new context, processed fresh at full price.
Cache writes: Claude saves the conversation so it doesn't re-process it next time. 1.25x input for a 5-minute cache, 2x for the 1-hour cache Claude Code mostly uses.
Cache reads: follow-up messages reuse the saved context at 10x to 40x less than input, depending on the model.
Output: what Claude writes back. The most expensive per token, usually the smallest amount.
Use /clear when you switch tasks. It resets the conversation so Claude stops re-reading context you no longer need.
Runs entirely on your machine: it reads your local Claude Code files and sends nothing anywhere. Costs are API list-price equivalents, not your plan's bill.
